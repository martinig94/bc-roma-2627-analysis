# LBA Serie A 2026/27 — game-by-game data

Incremental collector for the Italian basketball league (Lega Basket Serie A) 2026/27 season,
built on the undocumented JSON API behind [legabasket.it](https://www.legabasket.it).
It runs every morning on GitHub Actions, collects any newly finished games, and commits
the updated dataset — so `data/` grows on its own through the season.

Season context: 16 teams, 30 rounds (andata/ritorno). Two Rome teams — **BC Roma** (team_id 1761,
ex Vanoli Cremona) and **Maxima Roma** (team_id 1762, ex Germani Brescia).

## Data

| file | grain | notes |
|---|---|---|
| `data/games.csv` | one row per game (all 240 scheduled) | scores, quarter scores, venue, attendance, coaches; `game_status` 2 = finished |
| `data/box_scores.csv` | one row per player per game, plus `team` and `total` rows | minutes, pts, FG2/FG3/FT made+attempted, reb (O/D), ast, stl, tov, blk, fouls, `val` (LBA efficiency), `oer`, `plus_minus`, `starter` |
| `data/pbp.csv` | one row per play-by-play event | period, clock, running score, player, event type (Italian: "2 punti segnato", "Rimbalzo difensivo", "Ingresso"/"Uscita" = substitutions…), shot type qualifier, **x/y court coordinates (0–100)**, zone |
| `data/teams.csv` | teams of the season | team ids are re-issued each season — don't join across seasons on id |
| `data/raw/<game_id>/*.json` | untouched API payloads | lets you rebuild the CSVs offline (`python -m lba_data.rebuild`) |

Coordinates: `x` runs along the length of the court (each team attacks one half; `side`
flips per team/half), `y` across the width. Percent of court, not metres — calibrate
against the 3pt line (~6.75 m) before computing distances.

## Run locally

```bash
pip install -r requirements.txt
python -m lba_data.collect            # pull whatever is new
python -m lba_data.collect --limit 2  # test run
python -m pytest -q                   # unit tests against a real Round 1 payload
```

## Analysis starter

```python
import pandas as pd
box = pd.read_csv("data/box_scores.csv")
players = box[box.row_type == "player"]
roma = players[players.team.isin(["BC Roma", "Maxima Roma"])]
roma.groupby(["team", "player_surname"])[["pts", "reb", "ast", "val", "plus_minus"]].mean()
```

## The site (GitHub Pages)

`docs/` is a static site, generated by `python notebooks/weekly.py`. Team, season, author and the EuroCup file are set in
`weekly/config.json`. Every page has one dropdown at the top, **Opponents**: one entry per game (every competition), opening the opponent
analysis, which links to the BC Roma snapshot of the same game (a game without an analysis, e.g. an early EuroCup game, opens its snapshot):

| | what | data used | page folder |
|---|---|---|---|
| **BC Roma before the game** (link from the analysis) | BC Roma's situation before every game, **in both competitions** (LBA and EuroCup): LBA and EuroCup record, LBA standings, last results of both, last game's playing-time flag, team numbers (LBA and EuroCup columns), roster with photos, assist matrix and shot zones (LBA play-by-play), TS% vs PIR (LBA only, EuroCup only), every game so far | only games played before that game, in both competitions | `docs/snapshot/<date of the game>/` |
| **Opponent analysis** (the dropdown) | one per opponent and game, with the comparison table against BC Roma, results and standings, the opponent's roster with photos, starters and bench, scoring sources, shooting, hot spots, key players, lineups | only games played before that game: the league (LBA) plus the EuroCup, for the teams in the EuroCup file | `docs/opponent/<matchup folder>/` |
| **Game reviews** (landing page) | post-game: quarters, margin chart, team numbers, PIR vs average, playing-time flag, box scores, round results | through that game | `docs/review/round-NN/` |

**Every week** (the GitHub Action runs every morning at 06:40 UTC: it collects the games finished the day before, runs `weekly.py` and commits the result when there is something new; EuroCup games are not collected, add them to the EuroCup file and `weekly/schedule.csv`):

```bash
python notebooks/weekly.py --collect    # pull new games, generate everything that is missing, build docs/
# optional: write your text in the notes files it lists, then
python notebooks/build_site.py          # re-render the pages
git add -A && git commit && git push
```

`weekly.py --round 4` regenerates everything of one LBA round, `--game 2026-10-20` the snapshot of any game (stats corrections),
`--only snapshot,opponent,review` a subset; your text is never overwritten. The list of games (LBA from `data/games.csv`, EuroCup from
the EuroCup file, games still to play from `weekly/schedule.csv`) is `team_games.py`. A snapshot says when a game before it is not
in the data yet. The single steps are `snapshot_report.py --game DATE`, `opponent.py --round N`,
`weekly_report.py --round N` (review) and `build_site.py`.

* **Flags at the top of a page**: *Games still to be played before this one* (the page is a preview), *Played but not collected yet*
  (the data of an earlier game is missing; fixed by the next collection), and, for a game still to come, *Automatic draft, not reviewed
  yet* / *Work in progress*. The idea: the site first publishes everything automatically, then you review and improve. A page counts as
  reviewed when its notes file (`weekly/snapshot/<date>/notes.md`, `weekly/opponent/<folder>/notes.md`) has `reviewed: yes` in the header;
  without it the banner says draft (no text yet) or work in progress (some text). Pages with a hand-written README or `document.md`
  are reviewed by definition. `weekly.py` prints the upcoming games still to review, and the landing page shows the same on the cards.
* **Your text** goes in `weekly/<kind>/.../notes.md` (created empty): `title:`, `summary:` and `## key` sections of markdown,
  e.g. `key_points`, `form`, `roster`, `assists`, `zones`, `efficiency` for the snapshot; `key_points`, `comparison`, `starters`,
  `shooting`, `players`, `lineups`, `expect` for the opponent; `key_points`, `story`, `tactics`, `players`, `next` for the review.
  Empty sections are left out; put images in the same folder. An opponent folder `reports/matchup_*` with a hand-written
  `README.md` is shown as it is (the three first analyses are like that).
* **Layout**: `weekly/template/{snapshot,opponent,review}.md.j2` (page order, automatic parts, text slots) and `site.html.j2` (look).
  To add a section, add its key to the matching `notes_*.md` and an `{% if n.key %}...{% endif %}` block to the template, or add a
  figure in `weekly_sections.py` and its numbers to `auto` in the generator.
* **Next games** on the landing page: the next game to play in each competition (LBA from `data/games.csv`, the others from
  `weekly/schedule.csv`), each with its snapshot and opponent analysis. Those pages are generated ahead of the game and regenerated
  by `weekly.py` whenever new games enter the data (`n_before` in their `auto.json`) (`date,time,competition,opponent,home,analysis`, `home` 1/0; `analysis` =
  the `reports/matchup_*` folder). Add a row for every EuroCup game.
* **A document of your own for an opponent**: put it as `weekly/opponent/<matchup folder>/document.md` (images next to it). It is
  shown first, exactly as written, and the automatic report of that folder follows under "Automatic data report", so nothing of either
  is lost. The Manresa page is built like that from the Word document (`pandoc doc.docx -t gfm`, highlights kept as `<span class="mark">`).
* **Manresa photos**: `python notebooks/manresa_fetch.py` downloads them (EuroLeague roster API, needs network access to
  `api-live.euroleague.net`) into `data/manresa/photos/<surname>_<initial>.jpg`; or put your own jpg files there under those names
  (e.g. `notae_j.jpg`, `villar_r.jpg`). Then run `python notebooks/manresa_report.py --before 2026-10-18` and `python notebooks/build_site.py`:
  the pictures appear in the roster table of the document and in the automatic report.
* **Opponent figures** come from `matchup_report.py`, `lineups_report.py` and `standings.py` (`--before <date>`); each team's EuroCup
  games are added when the team is in the EuroCup file. Hand-written opponent pages get the roster with photos appended automatically
  (`roster.json` next to their README). Photos come from the league media server (box-score `player_p_key`); the Manresa report takes
  them from the EuroLeague roster API when `manresa_fetch.py` runs (`data/manresa/photos/`).
* **EuroCup data**: `python notebooks/eurocup_fetch.py` (run by the daily workflow; needs the EuroLeague API, i.e. network access to
  `api-live.euroleague.net`) writes `data/eurocup/results.csv` (every game of the season, through the
  [`euroleague-api`](https://github.com/giasemidis/euroleague_api) package), `people.csv` and `photos/` (rosters with headshots, from the
  club "people" endpoint). The snapshot of a EuroCup game shows the **EuroCup table of BC Roma's group** as of that date, computed from
  `results.csv` (a group = the teams connected through the schedule; ranking by wins, head-to-head, point difference), never the LBA table.
  Without `results.csv` the page says the standings are not available yet. EuroCup box scores are still the hand-made file
  (`data/eurocup_2026_raw.txt`).
* **Roster positions and heights**: `data/roster.csv` (new players are appended blank). Photos: `data/photos/` (fetched automatically).
* **Another team or season**: change `weekly/config.json`; the code has no team name in it.
* Enable the site once in the repository settings: Pages, source "Deploy from a branch", branch `master`, folder `/docs`.

## Caveats

* Not an official API. Endpoints were mapped from the site's network traffic in Sept 2026 and can
  change without notice — if a run fails, check `lba_data/api.py` first.
* Be polite: the collector sleeps between games and only fetches games it hasn't stored yet.
* Box scores appear within minutes of the final buzzer, but stats can be corrected in the days
  after. The collector doesn't re-fetch a game once stored; delete `data/raw/<game_id>` and
  re-run to refresh one.
* Playoffs are a separate championship id; add it with `--champ <id>` when the time comes.
